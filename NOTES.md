## Notes for next time

- CSV import field values must be individually double-quoted (RFC4180) if ANY field — including care-instruction strings — might contain a literal comma. Learned this the hard way mid-session: unquoted "Wipe clean with a soft, dry cloth" silently corrupted CSV column alignment for several rows.
- `npx prisma db execute --file <path>` remains the reliable way to run one-off SQL (still true: `npx tsx` importing `lib/prisma` fails silently). For multi-line JSON payloads, Postgres dollar-quoting (`$tag$...$tag$`) avoids manual single-quote escaping — used this for the `site_content` JSON writes. **New caveat**: `db execute` never prints `SELECT` results even on success ("Script executed successfully" with nothing else) — it's a DDL/DML runner, not a query tool. To read live rows (e.g. to get real product IDs for `data/reviews.json`), hit the app's own `/api/products`-style JSON route in the browser instead.
- The browser tool's ref-based clicks intermittently don't register on this project's pages (silently no-op, no error) even right after a fresh `read_page`; when a click doesn't visibly do anything, re-screenshot and click the raw pixel coordinate instead — reliable every time. Noted in a prior session's NOTES.md too, so this is a recurring environment quirk, not a code bug.
